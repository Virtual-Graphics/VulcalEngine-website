# 构建 Vulcal Engine 与打包游戏

使用 CMake 从源码构建引擎、编辑器和播放器。使用编辑器中的 **File → Build** 或命令行工具 `vulcal_build` 生成游戏包，并将已经构建的播放器复制到游戏输出目录。

## 从源码构建

### 环境要求

- Git、CMake 3.28 或更高版本，以及支持 C++23 的编译器。
- 首次配置需要联网，以下载第三方依赖。
- 运行编辑器、播放器或图形测试需要支持 OpenGL 4.6 的显卡驱动。

以下源码构建命令均在 VulcalEngine 源码根目录执行。

Vulcal Engine v0.0.5 以源码形式发布。从解压后的源码包构建时，无需保留 Git 仓库历史。

### 选择构建预设

有适用预设时，推荐先用 `cmake --preset <名称>` 配置，再用 `cmake --build --preset <名称>` 构建。预设记录了仓库支持的工具链和构建选项。运行 `cmake --list-presets=all` 可查看可用的配置预设和构建预设。

| 场景 | 推荐方式 |
| --- | --- |
| Windows 日常开发 | `msvc`，使用 Visual Studio 2026 和 MSVC。 |
| Windows 使用 Clang | `clang-debug` 使用 PATH 上的 `clang-cl` 和 Ninja，`vs-clangcl` 使用 Visual Studio 的 ClangCL 工具集。 |
| Windows 或 Linux 构建分发用播放器 | `release-static`，启用静态依赖，关闭测试和 Tracy。 |
| Linux 日常开发 | `linux-debug`，使用 Ninja 和系统默认的 C/C++ 编译器。 |

### Windows

安装 Visual Studio 的 C++ 桌面开发工作负载。使用仓库的 `msvc` 预设时，需要 Visual Studio 2026 和 x64 C++ 工具链。

```powershell
cmake --preset msvc
cmake --build --preset msvc --parallel
ctest --test-dir build -C Debug --output-on-failure
.\build\bin\Debug\vulcal_editor.exe
```

### Linux

在 Ubuntu 或 Debian 上安装构建和系统依赖。安装后确认 CMake 和编译器满足环境要求。

```bash
sudo apt-get update
sudo apt-get install -y \
    git build-essential cmake ninja-build pkg-config \
    libasound2-dev libdrm-dev libegl1-mesa-dev libgbm-dev \
    libgl1-mesa-dev libgtk-3-dev libudev-dev libwayland-dev \
    libx11-dev libxext-dev libxrandr-dev libxcursor-dev libxi-dev \
    libxinerama-dev libxkbcommon-dev wayland-protocols
```

```bash
cmake --preset linux-debug
cmake --build --preset linux-debug --parallel
ctest --test-dir build/linux-debug --output-on-failure
./build/linux-debug/bin/vulcal_editor
```

如需查看 OBJ 模型，可在同一 `bin` 输出目录运行 `model_viewer`，并传入模型文件路径。

### 预设参考

| 预设 | 工具链 | 配置 |
| --- | --- | --- |
| `clang` | PATH 上的 `clang-cl` 和 Ninja | 基础配置预设，使用时可指定 `CMAKE_BUILD_TYPE` |
| `clang-debug` | PATH 上的 `clang-cl` 和 Ninja | `Debug` |
| `clang-release` | PATH 上的 `clang-cl` 和 Ninja | `RelWithDebInfo` |
| `linux-debug` | Linux 系统默认的 C/C++ 编译器，Ninja | `Debug`，输出到 `build/linux-debug` |
| `msvc` | Visual Studio 2026，MSVC，x64 | 构建预设选用 `Debug` |
| `vs-clangcl` | Visual Studio 2026，ClangCL，x64 | 构建预设选用 `Debug` |
| `release-static` | 由 CMake 环境或配置命令指定 | `Release`，启用静态依赖，关闭测试和 Tracy |

Ninja 等单配置生成器在配置时用 `CMAKE_BUILD_TYPE` 选择配置，程序输出到构建目录下的 `bin`。Visual Studio 等多配置生成器在构建时用 `--config` 选择配置，程序输出到 `bin/<配置>`。

`msvc`、`vs-clangcl` 和 Clang 系列预设默认共用 `build`。如需在同一份源码中并行使用这些工具链，配置时用 `-B` 指定独立目录，随后用 `cmake --build <构建目录>` 构建。多配置生成器仍需指定 `--config`。

### CMake 选项

| 选项 | 默认值 | 说明 |
| --- | --- | --- |
| `BUILD_CORE` | `ON` | 构建 `vulcal_engine` 核心库。 |
| `BUILD_APPS` | `ON` | 构建编辑器、模型查看器、播放器和打包工具。 |
| `BUILD_TESTS` | `ON` | 构建测试并注册到 CTest。 |
| `BUILD_GRAPHICS_TESTS` | `OFF` | 在启用测试时加入需要 OpenGL 4.6 上下文的图形测试。 |
| `VULCAL_STATIC_DEPS` | `OFF` | 从源码构建随附依赖，避免发布的播放器依赖目标机器安装的 SDL3、spdlog 和 fmt。 |
| `VULCAL_ENABLE_PROFILING` | `OFF` | 启用 Tracy 性能分析。 |
| `VULCAL_ENABLE_GPU_PROFILING` | `ON` | 在 Tracy 启用时采集 OpenGL GPU 计时。 |
| `TRACY_ON_DEMAND` | `ON` | 在 Tracy 启用时，默认于分析器连接后开始采集。 |

有关采集时间线、GPU 计时和添加埋点，请参阅 [Tracy 性能分析](./profiling.mdx)。

### 着色器与图形测试

引擎在构建时嵌入内置着色器。修改 `vulcal_engine/render/shaders/` 下的着色器后，重新构建即可更新程序。运行时无需访问源码目录或外部 GLSL 文件。

默认测试无需图形显示环境。要运行图形测试，配置时加上 `-DBUILD_GRAPHICS_TESTS=ON`，然后重新构建并运行 CTest。图形测试需要可用的 OpenGL 4.6 显示环境。Visual Studio 构建运行测试时，使用与构建相同的配置，例如 `ctest --test-dir build -C Debug --output-on-failure`。

### 构建用于分发的播放器

使用 `release-static` 预设。Windows 下使用 Visual Studio 时，在构建命令中显式选择 `Release`。

```powershell
cmake --preset release-static -G "Visual Studio 18 2026" -A x64
cmake --build --preset release-static --config Release --parallel
```

Linux 下可以使用 Ninja。

```bash
cmake --preset release-static -G Ninja
cmake --build --preset release-static --parallel
```

Windows 的发布工具位于 `build/release-static/bin/Release`，Linux 的发布工具位于 `build/release-static/bin`。打包时使用这里的 `vulcal_player`。目标系统仍需具备运行游戏所需的系统库和图形驱动。

## 打包游戏项目

### 从编辑器打包

1. 在编辑模式下打开游戏的 `.vproj`。
2. 选择 **File → Build Settings…**，指定项目资源目录中的启动场景 `.vscene`。
3. 如需修改输出位置，选择构建输出目录，然后保存设置。未指定时使用游戏项目目录下的 `build`。
4. 选择 **File → Build**。编辑器优先在自身所在目录查找 `vulcal_build` 和 `vulcal_player`，随后查找 PATH。

启动场景和可选输出目录分别保存在 `.vproj` 的 `build_info.open_scene` 和 `build_info.build_dir` 中。启动场景使用项目相对路径，显式指定的输出目录以绝对路径保存。

### 从命令行打包

在编辑器中保存 Build Settings 后，也可以直接运行打包工具，并显式指定要随游戏分发的播放器。以下为 Windows 示例，将两个工具路径替换为实际构建产物的位置。

```powershell
.\vulcal_build.exe "C:\Games\MyGame\MyGame.vproj" ".\vulcal_player.exe"
```

构建输出包括 `<项目名>.vpak` 和传入的播放器可执行文件。`.vpak` 包含已处理的运行时资源、游戏场景、Lua 脚本和 `vulcal_game.vmanifest`。清单记录包格式版本、引擎版本、项目名称和启动场景。打包工具按原样复制播放器，因此游戏包的目标平台和播放器的 Debug 或 Release 行为由所选二进制决定。

### 运行打包后的游戏

将 `.vpak` 与播放器放在同一目录。直接启动播放器时，它会加载同目录中唯一的 `.vpak`。同目录存在多个游戏包时，启动时须显式传入包路径。

```powershell
.\vulcal_player.exe
.\vulcal_player.exe ".\MyGame.vpak"
.\vulcal_player.exe --log ".\MyGame.vpak"
```

在 Windows 上，`Debug` 播放器打开控制台并默认启用文件日志。`Release`、`RelWithDebInfo` 和 `MinSizeRel` 播放器以窗口程序启动，默认关闭文件日志。所有配置均可通过 `--log` 记录本次运行，包括启动阶段的错误。启用后，每次运行都会在播放器旁边生成一个独立的 `vulcal_player-*.log` 文件，因此该目录需要可写。
